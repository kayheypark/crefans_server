## 기존 프로모션 콩과의 차이

- 기존 프로모션콩(`bucket=promotion`): 받은 사람은 출금 불가, 후원에만 사용. 후원받은 크리에이터의 `earned-promotion` 로트가 되어야 출금 가능(출처 검사: 지급→후원 할당 대조).
- 레퍼럴 보상콩(2026-11-01 저녁 변경): 운영자 지급과 같은 `bean_promotions` 행(request_key `referral-reward:<signup id>`, actor `system:referral`)과 `promotion` 로트(유효기간 포함)로 적립한다. 받은 사람은 출금할 수 없고 후원에만 쓴다. (이전 설계: `earned-promotion` 로트로 바로 출금 가능)

## 구현(서버)

- 테이블: `referrals`(회원당 1행, id=초대 코드), `referral_signups`(초대받은 회원 1행, 보상 상태). 마이그레이션 `20261101090000_referrals`.
- 가입: `POST auth/signup/email/request`·`auth/signup`에 `referralCode`. 스위치 on + 유효 코드면 운영자 초대 없이 통과하고 가입 트랜잭션에서 관계를 기록. 스위치 off거나 코드가 없으면 기존 초대 규칙 그대로.
- 자격: 멤버십 `finalize`, 콩 충전 승인(`applyProvider` DONE) 트랜잭션 안에서 `qualifyReferralReward` → `qualified`, `grant_due_at=결제+7일`. **실결제(live)만** 인정(테스트 키 결제로 출금 가능 콩이 생기지 않게).
- 지급: 워커 `referral-rewards`(`grantDueReferralRewards`)가 기한이 지난 행을 처리. 원 결제가 환불됐으면 `pending`으로 되돌리고, 월 상한이면 `capped`, 아니면 적립 후 `granted`. 마이그레이션 `20261101120000_referral_hold`.
- 원장: 회사 재고(stock) → 추천인 `promotion` 100콩, 로트 `grant_id=bean_promotions.id`. `fundedLots`의 레퍼럴 예외는 삭제.
- 회수: 멤버십 `completeRefund`, 콩 `finishRefund`(부분 환불 포함)·`freezeCharge`(분쟁)에서 `clawBackReferralReward`. 보류 중이면 자격 취소, 적립 후면 남은 콩만 재고로 되돌리고 로트를 동결. 이미 후원에 쓴 몫은 회수하지 않음(미수금 없음, 2026-11-01 저녁 변경).
- 출금: 보상이 출금 불가로 바뀌어 `requireBeanPayoutMember`는 다시 크리에이터 전용(403 CREATOR_REQUIRED).
- 조회: `GET me/referral` — 코드와 집계(초대 수, 보상 건수·콩)만. 초대받은 회원의 개인정보·결제 정보는 돌려주지 않음.
- 검증(2026-11-01 저녁): referrals+beans+openapi 57 pass(커밋 ebb3406·46fe73e), 보상 로트를 `earned-promotion`으로 되돌리면 3건 실패(대조). 최초 검증: `tests/platform-referrals.test.cjs` 8건(대조: 출처 검사 제거 1건·live 조건 제거 3건·월 상한 제거 1건·보류 조건 제거 1건 실패), 기존 회귀 104건·jobs 2건 통과.
- 알려진 한계: 결제 트랜잭션에서 결제자 지갑 다음에 추천인 지갑을 잠가 잠금 순서가 고정 정렬과 다를 수 있음(교착 가능성 낮음, 재시도 대상).
