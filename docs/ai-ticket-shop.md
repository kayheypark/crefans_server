## 확인된 기존 구조

- 결제: Toss PaymentProvider는 서버 승인·조회·취소, 고정 멱등키, 결과 불명 상태를 유지. 콩 충전의 자체 원장을 AI 상품 판매에 혼용하지 않음.

## 공식 근거와 적용 판단
확인일 2026-11-14. 토스 v2 연동 가이드/v1 결제 API를 기준으로 한다.
- https://docs.tosspayments.com/guides/v2/get-started/payment-flow : 리다이렉트는 결제 인증 결과이며 서버 검증·승인 필요. 상품/금액은 서버 카탈로그에서 계산하고 구매 조건을 주문에 저장한다.
- https://docs.tosspayments.com/guides/v2/cancel-payment : 취소 API 멱등키·부분취소 지원. 기술적으로 가능한 범위와 사업자의 환불정책은 별개다.
- https://docs.tosspayments.com/reference/using-api/webhook-events : 결제/취소 이벤트는 서버 조회로 재검증. 콜백 입력만으로 지급하지 않는다.
- https://cheatsheetseries.owasp.org/cheatsheets/Third_Party_Payment_Gateway_Integration_Cheat_Sheet.html : 서버가 주문금액/통화/식별자·소유자를 검사하고 중복 콜백에 단1회 이행. 상품 재등록/가격 변경은 이미 승인한 주문의 구매조건을 변경하지 않는다.
- 전자상거래법 제17·18조 현행 페이지 검색 결과에서 청약철회/디지털콘텐츠 제공 개시 규정 확인. 국가법령정보센터 본문 열기는 시스템 점검으로 실패. 시행일·해당 서비스 적용·이용권 유형을 추가 확인해야 하므로 검색 요약만으로 사용 후 환불 제한을 확정하지 않는다. https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=282793

## 미결정 사업 정책
VAT 포함 가격/수량, 유료권 유효기간은 미결정이다. 횟수권과 잔여 비례 환불은 사용자가 결정했다. 결정 전 운영 판매 개시나 가격을 임의 설정하지 않는다.

## 화면 방향
서비스: 기존 스튜디오 톤의 상점/구매 내역. 상품별 실제 수량·VAT 포함 금액·유효기간·환불조건·구매 확인. AI 편집 초안을 유지한 구매 진입과 복귀. 광고상품 화면은 기존 링크로 유지.
콘솔: 기존 표/필터/등록·수정 모달, 조회/생성/수정/삭제 권한, 노출과 판매를 분리. 주문 상세는 결제/지급/사용/환불 상태와 요청ID 표시. 결제키·카드정보는 노출하지 않는다.

## 확정 및 구현 (2026-11-14 후속 사용자 응답)
사용자는 **횟수권**, **잔여 횟수 비례 환불**을 선택했다. 가격/묶음/유효기간은 콘솔 입력이며 초기 상품을 운영 DB에 넣지 않는다. 서버 `ai-shop.ts`, `ai-shop.controller.ts`, `ai-photo.ts`가 지급/차감/환불 경계이다. 금액100~1,000,000원, 수량1~10,000회, 유효기간1~3,650일은 입력 검증 범위이며 추천/판매 정책이 아니다. 1회 가격은 원 단위 정수여야 한다. 유효기간이 지나도 미사용분 환불 가능하며, 환불을 요청하면 남은 횟수 전체를 같은 결제수단으로 반환한다.

무료 횟수 소진 후 유료 횟수를 예약하며 성공 때 사용 완료, 실패 때 복구한다. 생성 중인 주문은 환불할 수 없다. 만료 임박 주문 우선 차감. 구매 스냅샷은 상품 변경/삭제 후에도 유지. 비정상 종료 예약은 1시간 후 복구(공급사 호출 제한보다 길다). `AiShopUse.id`는 생성 요청ID로 운영로그와 연결한다.

웹훅 `POST /shop/webhook`는 결제 재조회만 예약한다. PG 콘솔의 웹훅 등록은 이번에 하지 않았으며, worker가 기존 paid 주문을 1시간 간격 기준으로 조회하는 대사도 수행한다. 외부 취소는 자동 환불 완료로 가정하지 않고 review로 사용 차단. processing/refunding은 고정 주문·멱등키로 재확인하고 새 결제 승인하지 않는다.

실PG·카드사 판매 업종 계약 적합성은 검증하지 않았다. 운영의 기존 베타/실결제 제한을 변경하지 않는다. 운영자가 실제 판매를 켜기 전에 계약과 테스트 결제 흐름을 확인해야 한다. 이번 검증은 로컬 MySQL과 공급사 대역이다.
